### Звіт з виконання практичного завдання: Налаштування та використання Suricata IDS

**Мета роботи:** Встановити, налаштувати та запустити систему виявлення вторгнень (IDS) Suricata, додати власні правила та протестувати їхню працездатність.

### Крок 1. Встановлення та базова конфігурація Suricata IDS

Відповідно до лекційних матеріалів, Suricata — це потужний інструмент NIDS/IPS, який здійснює моніторинг мережевого трафіку для виявлення шкідливої активності на основі сигнатур.

Процес розгортання розпочинається зі встановлення необхідних базових пакетів у середовищі Kali Linux.

<img width="975" height="485" alt="image" src="https://github.com/user-attachments/assets/a3e29758-efb5-4b61-b2fb-88012bfc4408" />

**Рис. 1.** Встановлення пакета `software-properties-common`, необхідного для керування репозиторіями операційної системи.

Далі оновлюється список пакетів та встановлюється безпосередньо Suricata разом із утилітою `jq`. Утиліта `jq` є легковаговим інструментом для парсингу та обробки JSON-даних, що необхідно для зручного читання логів Suricata у форматі EVE JSON.

<img width="975" height="485" alt="image" src="https://github.com/user-attachments/assets/4e7c91a9-5d0b-4fcf-8733-3cc427ecf2e9" />

**Рис. 2.** Інсталяція Suricata та утиліти `jq` через пакетний менеджер `apt`.

Після встановлення необхідно налаштувати основний конфігураційний файл `/etc/suricata/suricata.yaml`. У ньому визначається локальна мережа, яку система повинна захищати.

<img width="975" height="485" alt="image" src="https://github.com/user-attachments/assets/5c98a3b8-109d-4640-9dc6-9a0f73c99fca" />

**Рис. 3.** Редагування файлу `suricata.yaml` у текстовому редакторі `nano` для правильного визначення діапазону IP-адрес у змінній `HOME_NET`.

Для ефективного виявлення загроз система потребує актуального набору сигнатур. Завантаження та оновлення правил здійснюється за допомогою команди `suricata-update`.

<img width="975" height="485" alt="image" src="https://github.com/user-attachments/assets/e82c398d-ce76-43bd-bc11-0a3eb692ad19" />

**Рис. 4.** Виконання команди `sudo suricata-update`, що демонструє успішне завантаження та оновлення правил від Emerging Threats.

### Крок 2. Додавання власних (Custom) правил

Для виконання наступного етапу завдання службу Suricata необхідно зупинити та додати власні правила виявлення. Щоб рушій зчитував локальні правила, файл `local.rules` спочатку активується у секції `rule-files` конфігураційного файлу.

<img width="975" height="485" alt="image" src="https://github.com/user-attachments/assets/aa425753-a6ac-4a52-aee6-4a3bc31e1cbe" />

**Рис. 5.** Підключення файлу `local.rules` до загальної конфігурації `suricata.yaml`.

Відповідно до синтаксису Suricata, правило складається з дії (наприклад, `alert`), заголовка (протокол, IP, порти) та параметрів (повідомлення `msg`, ідентифікатор `sid`, ревізія `rev`). У файл `/var/lib/suricata/rules/local.rules` було додано кастомне правило для виявлення ICMP-трафіку (пінг-запитів) із застосуванням унікального тексту сповіщення.

<img width="975" height="485" alt="image" src="https://github.com/user-attachments/assets/6923d58e-c0c5-4edb-b856-3c0f119f5292" />

**Рис. 6.** Створення власного правила: `alert icmp any any -> any any (msg: "Увага! Хтось пінгує мою віртуальну машину!"; sid: 10001; rev: 1;)`.

### Крок 3. Запуск Suricata та тестування працездатності правил

Для перевірки коректності конфігурації та успішного завантаження нових правил Suricata запускається із вказанням конфігураційного файлу (`-c`) та мережевого інтерфейсу (`-i`).


<img width="975" height="485" alt="image" src="https://github.com/user-attachments/assets/a851b882-482d-4176-9c0e-e0a9648d6d84" />

**Рис. 7.** Тестовий запуск Suricata (`suricata -c /etc/suricata/suricata.yaml -i eth0 -v`), завантаження 52160 правил та старт системи (Engine started) без помилок.

Для перевірки працездатності створеного правила навмисно генерується ICMP-трафік за допомогою команди `ping -c 4 8.8.8.8`. Після цього здійснюється перевірка файлу швидкого логування `/var/log/suricata/fast.log`.

<img width="975" height="485" alt="image" src="https://github.com/user-attachments/assets/d5f6e0aa-3547-43e2-a54e-cb08f4984996" />


**Рис. 8.** Результати тестування: у лог-файлі `fast.log` успішно зафіксовано багаторазове спрацювання власного правила (sid: 10001) із заданим повідомленням "Увага! Хтось пінгує мою віртуальну машину!".
